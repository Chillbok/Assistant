## 진행 방식

각 항목은 아래 사이클을 완료한 뒤에만 다음 항목으로 넘어간다.

1. **계획** — 그 항목만의 구현 계획을 세운다. 무엇을, 어디에, 어떻게 확인할지를 적는다. 항목 범위를 넘는 설계는 하지 않는다.
2. **구현** — 계획대로 만든다.
3. **검증** — 완료 조건을 실제로 실행해서 확인한다.
4. **정리** — 발견된 문제를 모두 해결하고, 결과와 배운 점을 이 문서에 남긴다.
5. **다음 항목** — 3번에서 문제가 하나라도 남아 있으면 넘어가지 않는다.

주의:
- 계획은 구현 직전에 세운다. 다음 항목의 계획을 미리 세우지 않는다.
- 진행 중 범위 밖 문제를 발견하면 그 자리에서 고치지 않는다. `# 보류 목록`에 적어두고 다음 항목 후보로만 남긴다.
- 한 항목의 계획이 길어지면 항목을 더 쪼갠다.

- 배운 점:
  - opencode 1.19.5는 V1 `permission` 객체만 읽는다. V2 `permissions` 배열은 exit 1로 거부하고, 오타 키는 경고 없이 무시되므로 `opencode debug agent build`로 deny가 실제 적용됐는지 확인해야 한다.
  - `OPENCODE_CONFIG` 경로에 파일이 없으면 조용히 기본 설정으로 실행된다. 설정 없이 도는 것을 막는 가드가 필요하다.
  - opencode는 첫 grep에서 ripgrep을 내려받아 `$XDG_CACHE_HOME/opencode/bin/rg`를 실행한다. 따라서 `/state`는 tmpfs(noexec)가 아니라 named volume이어야 한다.
  - `setsid -w`는 포크하지 않고 exec하므로 자식 pid가 곧 프로세스 그룹이다. `-f`를 붙이면 시그널 종료코드가 128+n이 아닌 raw 번호로 바뀌어 exit 15와 구분되지 않는다.
  - 리더가 이미 죽으면 `Process.Kill(entireProcessTree)`는 아무것도 하지 않는다. `kill(-pgid)`가 1차 경로여야 한다.
  - compose run 컨테이너는 `-T`가 없으면 TTY 때문에 stdout/stderr가 합쳐지고, `run`은 이미지를 재빌드하지 않는다.
  - 볼륨 최초 생성 상태는 root:root 755라 seed에서 `mkdir` 후 `chown` 순서를 지켜야 한다.
- 남은 일: 없음. 토큰 회전은 공개 직전 1회 실행한다(보류 목록).
- 보류한 위험: 홈 전체 동기화로 `~/.config/assistant/env`가 다른 기기로 복제된다. 컨테이너 안에서는 `/proc/1/environ`으로 토큰을 읽을 수 있다. 회전은 과거 복제본만 무효화하므로 두 항목은 별도로 다룬다.
